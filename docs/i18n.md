# Локализация интерфейса

Kubron «говорит» по-английски: **английский — базовый язык и fallback**, остальные языки — переводы
с английского. Решение и альтернативы — [ADR-0014](adr/0014-i18n.md). Библиотека — `vue-i18n` v11
(только Composition API).

## Устройство

```
frontend/src/i18n/
  index.ts           createI18n, t/te/tl, setLocale, initI18n
  languages.ts       реестр языков (код, название, правило множественного числа)
  format.ts          даты и числа в формате текущего языка
  backendErrors.ts   перевод ошибок Go-бэкенда (они приходят английскими)
  locales/<язык>/<раздел>.json
```

Имя файла — первый сегмент ключа: `locales/en/auth.json` → ключи `auth.*`. Английский вшит в бандл,
остальные языки подгружаются при выборе. Выбор хранится в `localStorage` (`kubron.locale`), по
умолчанию — язык системы, если он поддерживается, иначе английский. Бэкенд язык не знает.

## Как добавить язык

1. Скопировать `frontend/src/i18n/locales/en` в `locales/<код>` и перевести значения (ключи не трогать).
2. Добавить запись в `LANGUAGES` (`languages.ts`); для языков со сложным множественным числом — `pluralRule`.
3. Перевести ошибки бэкенда: `backend.json` в том же каталоге (раздел «Бэкенд»).
4. `npm run i18n:check` (из `frontend/`) — проверит полноту ключей и плейсхолдеры. Он же — отдельный шаг в CI (запускается до сборки).

## Правила для кода

**Шаблоны:** `{{ $t('section.key') }}`, `:title="$t('section.key')"`, с параметрами — `$t('k', { name })`.

**`<script setup>`:** `const { t } = useI18n()` (импорт из `vue-i18n`).

**Модули `.ts` (composables, resources, тосты):** `import { t } from '../i18n'` (путь относительный,
как во всём коде).

**Никаких `t()` на верхнем уровне модуля.** Модули импортируются до выбора языка, и текст
«застынет» на английском. Тексты, зависящие от языка, считаются внутри функции, `computed` или
рендера.

**Данные-описания** (колонки, пункты меню, свойства в `resources/definitions/**`): в поле
`label`/`title` лежит **ключ**, а рисующий компонент вызывает `tl(label)`. `tl` переводит строку,
только если это существующий ключ, поэтому пользовательские значения (имена CRD, kind'ы)
проходят как есть.

**Ошибки бэкенда** показываются только через `errorText(e)` (`composables/errorText.ts`): он
переводит сообщение. Никаких `e?.message || String(e)` в тостах и полях ошибок. Нельзя принимать
решения по тексту сообщения: для этого есть `isNotAuthenticated`/`isArgoTokenMissing`
в `i18n/backendErrors.ts`.

**Даты и числа:** `formatDateTime`, `formatDate`, `formatTime`, `formatNumber` из `i18n/format.ts`,
а не `toLocaleString('ru-RU')`.

**Не локализуем:** имена Kubernetes-объектов (Pod, Deployment, Namespace, ConfigMap…), поля YAML,
значения статусов из API (Running, CrashLoopBackOff), названия брендов (Kubron, Argo CD, Helm),
названия языков в переключателе. Подписи колонок, заголовки групп меню, кнопки, подсказки и
сообщения — локализуем.

## Ключи и тексты

- Ключ: `раздел.область.имя`, camelCase, глубина до 4: `auth.login.submit`, `resource.table.empty`.
- Один ключ — один смысл. Общие слова (Cancel, Save, Delete, Close…) — `common.*`, не дублировать.
- Английский: короткий, естественный, «Sentence case» (`Add cluster`, не `Add Cluster`), многоточие `…`.
- Русский: если в коде уже был русский текст — переносим дословно. Единая терминология:
  кластер, namespace, под (в тексте), узел, рабочая нагрузка, секрет, токен, роль, пользователь,
  пароль, войти / выйти, настройки, обзор, события, логи, терминал, проброс портов,
  синхронизация, откат, ревизия, манифест, лейбл, аннотация.
- Параметры — именованные `{name}`; набор параметров во всех языках одинаковый.
- Множественное число: английский `"{n} pod | {n} pods"` (2 формы), русский
  `"{n} под | {n} пода | {n} подов"` (3 формы: один | несколько | много); вызов `t('k', n)`.
- Служебные символы vue-i18n: `{ } @ $ |`. Литерально: `{'@'}`, `{'|'}`, `{'{'}`, `{'}'}`.
- Текст с разметкой (`<code>`, `<strong>`, ссылки): компонент `<i18n-t keypath="…" tag="p">` со
  слотами; `v-html` с переводом — запрещён.
- Строки в `<style>`, `console.*` и комментариях кода не переводятся.

## Бэкенд

Go-код возвращает ошибки и любые тексты для UI только по-английски и без форматирования «под
конкретный язык». Перевод — на фронтенде, таблицы в коде нет: английские шаблоны сообщений лежат
в `locales/en/backend.json` (формат Go, `%s/%d/%q/%v/%w` → `{p0}, {p1}…` по порядку), перевод —
те же ключи в `locales/<язык>/backend.json`. `translateBackendError` сопоставляет сообщение с
шаблоном: более конкретный шаблон имеет приоритет, а у составной ошибки `<префикс>: %w` префикс
переводится, причина — рекурсивно. Сообщение без шаблона (тексты client-go, сервера Kubernetes)
показывается как есть, по-английски.

Новая ошибка в `internal/**` (`errors.New("…")`, `fmt.Errorf("…")`) требует записи в `backend.json`
для **каждого** языка: `npm run i18n:check` сверяет Go-исходники (`internal/`, `pkg/`) с английской таблицей и
падает, если шаблона нет, и проверяет, что ключи есть во всех языках. Сообщения, по которым
фронтенд принимает решения (`authentication required`, `Argo CD API token is not set`), не
меняются без правки констант в `i18n/backendErrors.ts`.

Тексты, которые бэкенд формирует из данных (роли, действия аудита), отдаются идентификаторами
(`admin`, `Login`, …), а подписи — на фронтенде (`roles.*`, `audit.actions.*`). Заголовок нативного
диалога выбора файла приходит с фронтенда аргументом (`PickKubeconfigFile(title)`).

## Проверки

`npm run i18n:check` (или `node scripts/i18n-check.mjs`, `--strict` — предупреждения как ошибки):

- валидность JSON, одинаковые ключи и плейсхолдеры во всех языках;
- каждый `t('…')`/`$t('…')`/`<i18n-t keypath>` указывает на существующий ключ;
- кириллица в исходниках вне комментариев (тексты живут только в `locales/`);
- английские литералы в `<template>` (похоже на непереведённый текст) и неиспользуемые ключи.
