# Регрессия десктопа (задача 2.9)

Десктоп работает на корневом экземпляре ядра (`app.NewApp` в `main.go`): виды сессий (`NewSessionView`) создаёт только `kubron-server`.
Что изменилось для десктопа на этапе 2 и почему поведение должно остаться прежним:

| Изменение | Для десктопа |
|---|---|
| `auth.Service` = вид над общим состоянием | у корневого экземпляра одна неявная сессия, как раньше |
| лимиты `k8s.Limits` | терминалы и port-forward без ограничений, потоки логов 50 (прежний предел) |
| `connPool.getOrCreate` вне блокировки, singleflight | подключение строится так же; параллельные вызовы ждут один результат |
| `idleTTL` пула | 0 — informers останавливаются сразу, как раньше |
| события кластера через держателей пула | корневой менеджер — держатель своего активного кластера, получает `cluster:changed` |
| `Owner` терминала, `validStreamID` | веб-терминалы не используются; id логов `log_<uuid>` проходит проверку |
| `audit.Event.Source` | в десктопе пусто (`omitempty`) |

## Ручной прогон (`wails dev` или собранный бинарник, обычный каталог `~/.kubron`, без `KUBRON_DATA_DIR`)
1. Запуск: открывается экран входа (или первичной настройки), существующие пользователи и кластеры на месте.
2. Вход под администратором; смена роли/пароля пользователя в «Пользователи»; выход и повторный вход.
3. Кластеры: список, переключение между двумя кластерами (главный экран обновляется), добавление и удаление кластера.
4. Главный экран: данные обновляются сами при изменении в кластере (событие `cluster:changed`), без ручного обновления.
5. Терминал в поде: ввод/вывод, изменение размера окна, закрытие вкладки; несколько терминалов одновременно.
6. Логи: follow-поток, остановка, несколько потоков; после закрытия вкладки поток прекращается.
7. Port-forward: запуск, открытие в браузере, остановка; при выходе из учётной записи туннели закрываются.
8. Argo CD / Helm: открыть раздел, данные обновляются; фоновое событие не требует перезагрузки.
9. Автовыход по бездействию (при необходимости временно поставить 1 минуту): терминалы и port-forward закрываются.
10. Журнал аудита: действия записаны от имени вошедшего пользователя.

Отметьте любой пункт, который ведёт себя иначе, чем до этапа 2, и приложите вывод консоли `wails dev`.
