# Заголовки безопасности и защита от перебора

Относится к `kubron-server` (раздел 8 плана разработки). Настройка — переменные окружения или флаги.

## Заголовки

Выставляются на каждый ответ Go-сервера: страницы, статику, API, `/healthz`, страницы ошибок.

| Заголовок | Значение |
| --- | --- |
| `Content-Security-Policy` | `default-src 'self'`; `script-src 'self'` (без `unsafe-inline` и `unsafe-eval`); `style-src 'self' 'unsafe-inline'`; `img-src 'self' data:`; `font-src 'self'`; `connect-src 'self'` + `ws://` и `wss://` своего хоста; `worker-src 'self' blob:`; `object-src 'none'`; `base-uri 'self'`; `form-action 'self'`; `frame-ancestors 'none'` |
| `Strict-Transport-Security` | `max-age=31536000`, **только** для защищённого запроса (TLS или `KUBRON_TRUST_PROXY=1` + `X-Forwarded-Proto: https`) и не на loopback. `includeSubDomains` и `preload` не включены: это решение владельца домена |
| `Permissions-Policy` | camera, microphone, geolocation, payment, usb и др. отключены |
| `Cross-Origin-Opener-Policy` / `Cross-Origin-Resource-Policy` | `same-origin` |
| `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy` | `nosniff`, `DENY`, `no-referrer` |

**Почему `style-src 'unsafe-inline'`.** Monaco и xterm создают элементы `<style>` на лету, так же
подключается шрифт codicon (`MonacoEditor.vue`, `TabbedPanel.vue`). Без этого редактор остаётся без
стилей. Исключение действует только для стилей, скрипты остаются `'self'`.

**CSP отдаёт только сервер.** `<meta http-equiv="Content-Security-Policy">` в `index.html` нет: он
затронул бы десктопную сборку Wails.

**Обкатка.** `KUBRON_CSP_REPORT_ONLY=1` (`--csp-report-only`) отдаёт политику как
`Content-Security-Policy-Report-Only`: нарушения видны в консоли браузера, ничего не блокируется.
Отправки отчётов на сервер нет.

## Адрес клиента за прокси

Адрес клиента нужен журналу аудита и блокировке перебора. Клиент может подделать левую часть
`X-Forwarded-For`, поэтому адрес берётся **справа**, после доверенных прокси. Всё это работает
только при `KUBRON_TRUST_PROXY=1`.

| Настройка | Смысл |
| --- | --- |
| `KUBRON_TRUSTED_PROXY_HOPS` (по умолчанию 1) | Сколько доверенных прокси стоит перед сервером, считая прямого собеседника. Клиент — элемент `X-Forwarded-For` с индексом `len-hops`. Цепочка короче ожидаемой (запрос в обход прокси) — берётся адрес собеседника |
| `KUBRON_TRUSTED_PROXIES` | CIDR или адреса доверенных прокси через запятую. Если задан, заменяет счётчик: собеседник обязан входить в список (иначе заголовок игнорируется), клиент — первый справа адрес вне списка |

Примеры: ingress-nginx за облачным балансировщиком — `KUBRON_TRUSTED_PROXY_HOPS=2`; ingress в
известной сети — `KUBRON_TRUSTED_PROXIES=10.0.0.0/8`. При любой неоднозначности (мусор в заголовке)
используется адрес прямого собеседника. Ключ ограничений для IPv6 — префикс `/64`.

## Ограничение попыток

- **Вход и смена пароля.** 5 бесплатных попыток на логин, 30 на адрес за 15 минут, затем
  экспоненциальная блокировка до 5 минут; отказы пишутся в аудит с адресом (`source`). Подбор старого
  пароля через `ChangePassword` считается так же. `SetupAdmin` перебирать нечего (работает, пока нет
  пользователей), он ограничен общим лимитом ниже.
- **Анонимные RPC-вызовы** (без сессии, включая `Login` и `SetupAdmin`): token bucket по адресу,
  20 запросов сразу и 5 в секунду. Ответ — `429`, `Retry-After`, тело `{"error": {"code": "rate_limited", "message": …}}`.
- Записи о неудачах хранятся раздельно для логинов и адресов. При заполнении вытесняются сначала
  устаревшие, затем самые старые записи **без** блокировки; действующие блокировки не сбрасываются.

**Ограничение: состояние в памяти процесса.** Счётчики входа и token bucket не общие между
репликами; с несколькими репликами лимиты действуют на каждую отдельно. Поддерживается одна реплика
(HA — этап 4).
